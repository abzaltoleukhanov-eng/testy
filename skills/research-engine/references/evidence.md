# Слой B. Журнал доказательств

## Источник ≠ доказательство ≠ утверждение
- **Источник** (`archive/sources.jsonl`): что реально получено. Пишет скрипт сбора: ссылка, id, кто (хэш автора), когда, как получено (`retrieval_method`), что видели (`access_status`, `context_captured`), полный текст.
- **Доказательство** (`evidence.jsonl`): одно наблюдение из одного источника. Пишешь ты через `ledger.py add evidence`.
- **Утверждение** (`claims.jsonl`): вывод, который может попасть в бриф. Ссылается на доказательства.

## Поля доказательства и как их заполнять
| Поле | Как заполнять |
|---|---|
| `quote_span` | дословный фрагмент из текста источника; скрипт отклонит запись, если фрагмента нет |
| `observation` | что сказано, нейтрально, по-английски или по-русски |
| `observed_behavior` | что человек **сделал**: вернула, продолжает носить, купила органайзер, перешла на рюкзак. Если только мнение, пиши `opinion only` |
| `person_action` | `NONE` · `CONSIDERED` · `POSTPONED` · `BOUGHT` · `REJECTED` · `RETURNED` · `SWITCHED` · `USES` · `STOPPED_USING` · `WORKAROUND` |
| `product_match` | `EXACT_SKU` (именно наш артикул) · `SAME_PRODUCT_FAMILY` (Siena Lévant, другой вариант) · `SAME_BRAND_OTHER_PRODUCT` · `COMPETITOR` · `CATEGORY_GENERAL` · `UNKNOWN`. Отзыв о Belted Tote не подтверждает свойства обычного Tote |
| `usage_situation` | конкретная ситуация из текста; не выдумывай, если не видно — `UNKNOWN` |
| `situation_cluster_id`, `behavior_pattern_id` | короткие id, которые ты присваиваешь при группировке (`S03`, `BP07`); нужны для подсчёта новизны |
| `market_grounding` | `EXPLICIT` (страна названа), `INFERRED` (по словам вроде «Tube», «Target»; только как подсказка), `UNKNOWN` |
| `story_id`, `independence_group` | заполняй, только если можешь объяснить, почему история независима. Иначе скрипт считает весь тред одной группой |
| `what_it_does_not_prove` | обязательно: распространённость, возраст, мотив покупки, свойства нашего SKU и т.д. |

Возраст и пол пиши только если человек назвал их сам.

## Decision Evidence: истории решений
Если человек описывает решение, `evidence_kind: "DECISION"` и блок `decision`:
`initial_situation`, `alternatives_considered`, `decision_trigger`, `action_taken`, `reported_outcome`, `reason_basis` (`EXPLICIT` / `INFERRED`), `unverified_assumptions`.

«Мне не нравится тяжесть» — это жалоба (`OBSERVATION`). «Я вернула сумку, потому что с ноутбуком она оказалась слишком тяжёлой» — это решение с названной причиной (`DECISION`, `RETURNED`, `EXPLICIT`). Но рассказ о покупке не доказывает её истинный психологический мотив; это фиксируй в `unverified_assumptions`.

## Независимость
- Комментарии одного треда по умолчанию одна группа: участники повторяют друг друга и автора поста.
- Отдельная группа внутри треда допустима, если это самостоятельная история с собственными деталями. Тогда задай `independence_group` и объясни в `notes`.
- Один автор на разных площадках — неизвестно, разные ли это люди; не считаем их независимыми автоматически.

## Типы утверждений и чего каждому хватает
Пороги лежат в `contract.json → gates`, здесь смысл:
| Тип | Что утверждаем | Чего достаточно |
|---|---|---|
| `PERSONAL_EXPERIENCE` | с этим человеком было так | один прочитанный источник |
| `PATTERN` | это повторяется у разных людей | ≥3 независимые группы из ≥2 тредов, ≥2 ситуации или площадки, контрпоиск |
| `PURCHASE_DRIVER` | это влияет на покупку / отказ / возврат | ≥2 независимые истории решений + контрпоиск |
| `PRODUCT_FACT` | у нашего SKU есть свойство | официальная страница, прочитанная полностью, или скриншот пользователя |
| `PRODUCT_PERFORMANCE` | наш продукт ведёт себя так в жизни | опыт владельцев именно этого SKU или семейства |
| `SITUATION_REACH` | ситуация массовая | никогда не факт: только помеченные косвенные признаки |
| `HYPOTHESIS` | наша догадка | всегда можно, с меткой |

Сначала определи тип утверждения, потом ищи доказательства этого типа. Если не хватает, сузь формулировку («у части владельцев ноутбуков…») или понизь до гипотезы.
